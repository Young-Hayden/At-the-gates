## 1. 目标与边界

本次是收尾，不扩张玩法：

1. 补测其他功能与实际玩法，只修稳定复现、根因明确的问题。
2. 保留现有像素木牌风格、HUD 布局与操作习惯，提高文字和面板可读性。
3. 最终交付完整回归、真实运行截图、Console 与文件完整性证据。

不包含：难度系统、小地图降频、音效、整体布局重排、数值平衡重做、独立播放器打包、真人操作系统级键鼠自动化。

## 2. 方案比较与决定

- **采用方案 A：玩法定点验收 + HUD 可读性精修。** 保留布局和风格，修改范围与回归风险最小。
- 不采用方案 B：同时重排资源栏、生产栏和选中面板。虽然能扩大战场视野，但场景修改和分辨率回归成本更高。
- 不采用方案 C：重建 HUD。可能覆盖既有手修布局，不适合收尾。

## 4. 第 2 部分：HUD 清晰易读精修

### 4.1 保留项

- 保留 ResourceBar、BuildBar、UnitPanel、SelectionPanel、ProductionPanel、MinimapPanel 的位置、尺寸、锚点和点击区域。
- 保留像素木牌、现有头像、按钮图标、生产进度、小地图与主菜单。
- 保留 Cost 底边 `y=10`、Name `y=26/h=15`、Button `y=41/h=56`。经用户对实测溢出的明确裁决，Cost 高度由 `14→15`，顶边为 25，与 Name 底边仍留 1px；其他矩形不变。

### 4.2 面板底衬

- ResourceBar、BuildBar、UnitPanel 现有 Backing：黑色不透明度 **0.40 → 0.58**。备份证明 ResourceBar 原有 **8px** 内缩，BuildBar 原有 **6px**，UnitPanel 原有 **6px**；全部保持原值，不得为统一样式改变既有布局。
- SelectionPanel、ProductionPanel：各新增或复用一个名为 `Backing` 的内嵌深色底衬，颜色与上述一致。
- 新底衬相对面板四边内缩 **6px**，位于文字和交互控件下层，不接收 Raycast，不遮住木框。
- MinimapPanel 不在本轮修改。

### 4.3 文字与运行时配色

- 主文字固定为 `(1.00, 0.96, 0.86, 1)`（约 `#FFF5DB`）；说明/标题辅助文字固定为 `(0.95, 0.90, 0.78, 1)`（约 `#F2E6C7`）。底衬加深后不添加模糊描边。
- `PolishHUD.ValueTint`、`CostTint` 使用上述主文字色，`CaptionTint` 使用上述辅助色；SelectionBody 与生产标题按各自语义使用同一组颜色。
- UnitName：**13 → 14pt**；UnitCost：**12 → 13pt**。preferred size 必须适配。UnitCost 高度按用户裁决为 15px，不保留已实测无效的自定义 0.95 行距；不得靠放宽 fit 断言通过。
- 警告保留琥珀色，缺资源、人口、食物和队列原因的判断顺序不变。
- 同步 `HUD.cs` 中运行时颜色，特别是正常 UnitCost 当前硬编码的颜色，避免每帧刷新覆盖场景样式。
- 同步 `PolishHUD.cs` 的样式常量，保证以后工具生成结果与交付场景一致。
- 生产建筑标题复用 `BuildingTitle`，显示“兵营/靶场”等中文；存档对象名和预制体名不变。

### 4.4 实施边界

- 使用新的增量修补入口，仅处理上述目标；不重跑完整 BuildHUD。
- 场景保存前必须单独给出风险+收益表，备份 `SampleScene` 并记录 MD5。
- 保存后执行对象级审计：目标外新增/删除为 0，动画速度和 AI 字段无附带变化；发现序列化噪声必须清理或回滚。

## 5. 测试与视觉验收

3. UnitName/UnitCost 字号符合设计，preferred size 不超矩形，Cost/Name/Button 不相交。
4. 正常与警告 UnitCost 在运行时刷新后仍使用目标配色。
5. 生产标题使用中文并保留未知对象名回退。
