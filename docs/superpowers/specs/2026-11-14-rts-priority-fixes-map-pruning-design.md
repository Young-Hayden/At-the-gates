# 《兵临城下》优先修复与地图减量设计

日期：2026-11-14  
工程：`D:\Unity\projects\At the Gates`  
基线：`main@3e5659a`  
状态：设计已获用户批准；实施计划待编写。

## 1. 目标与范围

按已复现问题的优先级完成四项修复，并适度减少地图装饰：

1. 修复无基地、低资源、无单位建筑时无法判负的问题，覆盖玩家与 AI。
2. 修复羊步行中途保存后，读档位置与逻辑占地错位的问题。
3. 暂停和结算时禁止小地图点击移动镜头。
4. 修正一个 `Tree1` 实例的位置/占地偏移，不改变既有阻挡格。
5. `Garnish` 下陆地草由 99 丛减至 50 丛，分区保留；只删除 Bush 根对象。

明确不做：不减少资源树、羊、建筑、单位、地形、水岩、海岩或云；不重建整个装饰层；不修改真实存档；不做无关重构；不添加音效；不保存其他场景。

## 2. 方案选择

采用**定点修复 + 分区减量**。

不采用完整羊移动状态序列化：该方案需保存方向、起点、终点、已用时间、连续步数、原占地和锚点，并处理旧档迁移；对当前问题而言成本与风险过高。

不采用重新运行装饰生成器：生成器会重建或重排非目标装饰，难以保证对象级差异仅限于批准范围。

## 3. 判负修复

### 3.1 玩家

`GameState.CanStillRecover` 在遍历 HUD 建造表时，除 `Economy.CanAfford` 外，还必须应用与放置入口一致的前置规则：

- 指挥中心：价格合理且当前没有存活指挥中心时，才是恢复手段。
- 非指挥中心：只有存在完工指挥中心时才可计入；在“无单位、无建筑”的团灭检查语境下，这意味着它们不能被当作恢复手段。
- 空预制体和缺少 `Building` 的条目忽略。

真实 HUD 不存在时，`recoveryGoldFloor` 是无建造表场景的显式兜底。默认值及 SampleScene 序列化值均由 50 改为 300，与当前主基地价格一致；注释不再把 50 金民房描述为无基地时的恢复手段。

### 3.2 AI

`AIController.CanStillRecover` 必须与实际 `Build()` 顺序一致：

- 从 `nextBuild` 开始跳过 null 项，只检查第一个实际会尝试的预制体。
- 不得扫描后续便宜建筑并据此判定有恢复能力。
- 应用价格、完工指挥中心前置和单指挥中心规则。
- 没有剩余可尝试项目时返回 false。

### 3.3 验收

覆盖 75、299、300 金边界；玩家与 AI 的指挥中心/民房前置；AI 后续民房不能挽救当前 300 金指挥中心；正常有恢复能力状态不得误判负；既有团灭测试继续通过。

## 4. 羊中途存档修复

采用**回到最后一个完整占地格**，不新增存档版本或移动状态字段。

`SheepWander` 在步行中，`Building.Cells` 仍表示最后一个已完成步伐的逻辑占地，而 transform 正在两格之间插值。`SaveGameService` 写建筑记录时，如果对象带正在步行的 `SheepWander`：

- 位置记录为由当前 `Building.Cells` 与宽度推导出的稳定原点，而不是插值中的 transform。
- y 使用当前逻辑占地行，z 保持原值。
- 资源量、重生状态、旋转和缩放仍走现有保存路径。
- 不修改保存时的实时对象；只改变写入记录的位置。

读档后羊静止在保存前最后一个合法占地格，最多回退不到一格。这样不会引入半格原点、非法目的地或新旧占地不一致。

验收覆盖横向中途保存、资源量保持、读档后 `IsWalking=false`、位置与 Cells 一致、阻挡格与保存前逻辑占地一致，以及旧版没有附加字段的存档继续可读。

## 5. 小地图模态输入

`Minimap.OnPointerClick` 在处理左键前增加与 `RTSCamera` 一致的模态闸：

- `PauseMenu.IsAnyOpen` 为 true 时直接返回。
- `GameState.Instance != null && GameState.Instance.IsOver` 时直接返回。

正常对局中的点击跳转不变。测试同时保留未暂停正对照，避免把输入全部禁用。

## 6. Tree1 定点校正

目标实例：`Tree1 @ (4.37,18.44,0)`。

将其 x 调整为 `3.50`，y/z 不变。调整后根格为 `(3,18)`，与该对象调整前已经计算并阻挡的 `(3,18)` 一致。

不得把阻挡格从 `(3,18)` 改到 `(4,18)`；后者本来由 `Deco_08` 占用。保存前后须验证目标 Tree1 的逻辑占地不变，并确认 ProjectDoctor 的 Footprint 计数由 1 降为 0。

## 7. 草地分区减量

只处理 `Garnish` 的直接子对象中名称以 `Bush` 开头的 99 个根对象。它们没有 `Building` 或 `Collider2D`，不阻挡移动、不提供资源，但会限制建造格。

减量算法：

1. 按世界坐标划分 10×10 格区块。
2. 各区块按 49/99 的总比例分配删除数，使用最大余数法保证总数恰好 49。
3. 区块内优先删除靠近双方初始建设区域的草，再删局部密度高的草，最后按稳定坐标排序，避免依赖 Unity 对象遍历顺序或随机数。
4. 保留 50 丛，确保不同区域都保留装饰，不把地图一侧全部清空。
5. 不重排保留对象，不改其坐标、缩放、Sprite、Animator 或 ClearableBush 参数。

旧真实存档不写；继续旧档时草仍按该存档内容恢复，减量主要作用于新游戏。

- 动画速度和 AI 权重不得出现附带变化；存在未批准差异则不保存或立即字节回滚。
