# 2026-10-27 RTS 高价值健壮性收尾设计

## 背景与目标

第一批七项修复及 B09 最终返修已完成，最终完整 PlayMode 为 81/81 通过。真实物理输入验收因 Windows 锁屏暂时无法继续，其余高价值收尾可以独立完成。

本子项目采用用户批准的方案 A，目标是补齐 A04 的完整存档证据、增强 D01 修复工具和空图标行为、加固 D04/C01 回归测试，然后重新评估是否进入 A01＋A02。

## 范围

1. A04：在建塔与驻弓箭手的完整存档往返及血条防御。
2. D01：`RepairProductionPanel` 的预检、字体回退和空图标行为。
3. D04/C01：测试判别力加固。
4. 相关回归、完整 PlayMode 和结果报告。

## 非目标与约束

- 不实施 A01/A02、AI 重建/驻塔、性能重写、人口、科技、LOS 或单位物理改造。
- 不全量重建 HUD，不改变现有布局、建筑数值、生产价格或存档版本。
- 不修改正式存档槽；所有存档测试使用测试路径。
- 不安装 Input System。锁屏期间不继续 Windows 输入注入；真实输入验收保留为待办。
- 保留全部既有未提交修改，不提交、不推送、不清理工作区。
- 测试失败或未执行时必须如实报告，不以历史绿灯替代当前结果。

## A04：完整在建驻塔存档恢复

### 行为

- 构造一座 `MarkBuiltDuringMatch()` 的在建塔，并通过 `RestoreGarrison` 建立旧存档可能存在的驻兵关系。
- 使用正式 `SaveGameService.CaptureSnapshot`、文件写入/读取及 `RestoreSnapshot` 完整往返。
- 恢复后：塔仍在施工、驻兵关系存在、弓箭手生命保留、完工前没有弹丸。
- 完工后：既有开火路径恢复，能够生成弹丸。
- `TowerGarrison.Update` 的防御性血条隐藏放在死亡/预览/在建早退之前；即使其他逻辑重新显示血条，下一次 Update 也会再次隐藏。

### 测试

- 新增独立 PlayMode 往返测试，不只直接调用 `RestoreGarrison`。
- 强制让驻兵血条可见，验证在建 Update 会隐藏它。
- 使用完工塔的现有测试作为正控制，确保早退移动没有破坏正常开火。

## D01：修复工具和空图标

### 预检与原子性

`RepairProductionPanel` 在任何对象创建或字段写入之前检查：

- `produceButtons`、`produceIcons`、`produceCosts` 非空；
- 三个数组长度一致；
- 每个待修复按钮非空且具有 `RectTransform`。

结构无效时抛出带槽位/数组信息的 `InvalidOperationException`，不创建子物体、不标记或保存场景。正常场景的三槽配置保持原样。

### 字体

- 与 `Build()` 一致，先 `LegacyRuntime.ttf`，不可用时回退 `Arial.ttf`。
- 只有取得有效字体时才覆盖现有 `Text.font`，避免把既有可用字体写成 null。

### 空图标

- `EnsureIcon` 在 sprite 为空时禁用 Icon Image，非空时启用。
- `HUD.RefreshProduction` 每次设置产品图标时同步 `enabled = want != null`，保证“初始为空、后来有图标”和“有图标、后来为空”都能正确显示。
- 不改变有正常图标时的尺寸、材质、颜色、Raycast 和布局。

### 验证

- 编辑器探针验证畸形数组在修改前被拒绝，正常三槽仍可修复。
- PlayMode 验证空图标不显示白色 Image，获得有效产品图标后恢复显示。

## D04／C01：测试加固

- `QuickBuild_SceneOrder_MatchesBuildMenu` 除既有名称顺序外，直接断言每槽 `placer.quickBuild[i] == hud.buildPrefabs[i]`，并检查数组长度一致。
- 有效快捷建造测试使用两个不同 prefab，调用索引 1，验证创建的是第二个 prefab 的 ghost；生产入口已存在后直接调用，不再依赖反射。
- 非法索引测试改为 `UnityTest`，非法调用后等待一帧，再确认原 ghost 仍是唯一实例。
- C01 在恢复后记录 `amountAtRestore`，最终断言 `node.amount < amountAtRestore`，避免恢复前已采集导致假通过。
