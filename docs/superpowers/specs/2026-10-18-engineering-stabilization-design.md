# 工程稳定化设计：建造、寻路指令、场景占地、Doctor 与回归测试

日期：2026-10-18
项目：`D:\Unity\projects\At the Gates`

## 1. 背景与目标

当前工程已确认存在放置校验缓存失效、幽灵注册真实占地、旧路径穿越新阻挡、采集不可达时每帧寻路、手动移动被自动任务覆盖、死亡单位残留选择集，以及部分场景物体根格与占地不一致等问题。

本次只实施用户选定的五项：

1. 建造系统稳定包；
2. 寻路与指令稳定包；
3. 场景占地清理包；
4. Project Doctor 工程体检工具；
5. 自动回归测试场景。

目标是修复已知稳定问题、清理已确认的场景数据，并用可重复运行的自动检查防止回归。不扩展玩法。

## 2. 已确认的决策

- 场景对齐以物体当前根格为准；根格仍非法时不强行移动，列入报告。
- 普通右键移动后，工人保留携带资源并原地待命；下一次明确采集或清草指令恢复工作。僧侣只治疗射程内伤兵，不再远程追击。
- 测试使用项目已安装的 Unity Test Framework 1.1.33，采用 Runtime asmdef、独立 PlayMode 测试 asmdef 和隔离测试场景。
- 隔离测试场景不加入正式 Build Settings。

## 3. 建造系统稳定设计

### 3.1 统一校验

增加共享的占地校验入口，复用现有 `MapGrid.TerrainWalkable`、`IsRamp`、`IsBlockedByBuilding`、`Level` 和单位格换算。玩家与 AI 使用相同的地形、坡度、建筑重叠及单位占位规则；各自保留资源、科技条件和 AI 的建筑间距规则。

### 3.2 提交前原子复验

`BuildingPlacer.Place()` 在扣款和实例化之前重新执行完整校验，不再依赖此前缓存的 `lastValid`。放置后使预览校验缓存失效，确保同格再次放置会读取新建筑占地。资源仍只通过现有 `Economy.TrySpend` 扣除，失败时不实例化。

### 3.3 幽灵生命周期

幽灵预制体实例化时，`Building.Awake/OnEnable` 可能已注册占地。创建幽灵后通过明确的幽灵初始化入口撤销该注册，并继续保持幽灵不进入 `Building.All`、不作为卸货点、不参与碰撞和生产。取消或替换幽灵不得删除其他真实建筑的占地。

### 3.4 输入消费

`BuildingPlacer` 记录右键取消发生的世界输入帧。`SelectionManager` 在同一帧跳过世界命令，避免取消建造同时触发移动、采集或攻击。

## 4. 寻路与指令稳定设计

### 4.1 动态阻挡

`UnitMover` 同时保存路径格与世界坐标点。前往下一格前使用 `MapGrid.Walkable` 检查该格；若已不可走，清除旧路径和到达回调并停止。不得在阻挡时触发伪到达。上层采集、战斗或治疗逻辑可在各自既有节奏下重新规划。

### 4.2 不可达采集

采集寻路失败进入有时间间隔的重试，不得每帧运行 A*。障碍移除后允许同一任务恢复。自动派工只考虑与工人处于同一连通区域、且存在可接近格的资源点。

### 4.3 手动移动优先

普通移动调用明确的任务取消入口：

- `Gatherer` 清除资源、清草和卸货目标，保留携带资源，进入手动待命；自动上岗和定时重新派工在手动待命期间停止。
- 新的明确采集或清草指令解除手动待命。若持有资源，先卸货，再执行新任务。
- `Healer` 清除远程病人和旧路径，进入原地治疗状态；只从治疗射程内选择伤兵，不执行远程追击。
- `SelectionManager` 每帧从选择集中移除已死亡对象，即使其尸体对象尚未销毁。

## 5. 场景占地清理

仅处理 `Assets/Scenes/SampleScene.scene` 中审计发现的根格不在自身占地内的对象。

1. 修改前在 `Assets` 外保存场景备份。
2. 对每个目标对象读取当前根格。
3. 目标根格必须地形可走、非坡道，且修正后不会与其他真实建筑重叠；不满足时跳过并报告。
4. 合法时把根节点吸附到该格标准接地点，调用现有占地重算入口。
5. 保存 `SampleScene`，不重排其他装饰、不重新生成地图、不修改其他场景。

## 6. Project Doctor

新增只读编辑器检查与文本报告，检查：

- 根格与自身占地不一致；
- 重叠占地、无地面占地、坡道占地；
- 重复管理器；
- Missing Script 和真正丢失的对象引用；
- 世界素材 PPU 64、Point 导入规则；
- Animator 普通曲线和 Sprite 对象引用曲线的绑定路径，路径相对 Animator 所在对象解析。

Doctor 不调用现有生成/修复菜单，不自动修复，不保存场景，不执行 `SaveAssets`、`SaveAndReimport` 或重新导入。摘要输出到控制台，完整报告写入项目根目录 `Logs/`。编辑模式不伪造对运行时幽灵和动态阻挡的证明，这些由 PlayMode 测试覆盖。

## 7. 自动回归测试

### 7.1 结构

- 为现有运行脚本增加 Runtime asmdef，保留现有脚本 GUID 和场景/预制体引用。
- 新增独立 PlayMode 测试 asmdef，引用 Runtime、Unity Test Framework 和 NUnit。
- 新建隔离的 `RegressionTests.scene`，只含测试所需网格、管理器和相机，不包含正式地图、HUD、AI 或装饰。
- 通过编辑器菜单和 `TestRunnerApi` 运行并输出逐测试及汇总结果，便于 MCP 调用。
- 测试不保存场景，不修改 Build Settings，不在 `SampleScene` 中创建测试对象。

### 7.2 回归用例

1. 同格第二次建造失败，真实建筑数和扣款次数不增加，第一栋建筑占地保持有效。
2. 幽灵创建、移动和取消前后真实占地快照一致，幽灵不进入 `Building.All`，不影响已有 blocker。
3. 新阻挡使旧路径停止，单位不进入被阻挡格，原到达回调不触发。
4. 不可达采集不每帧寻路、不远程收获；恢复连通后能够继续任务。
5. 普通移动后工人保持手动待命，僧侣不远程追击，只接受射程内病人。
6. 已死亡但未销毁的单位退出选择集，不能继续接收移动命令。
7. 隔离场景重载后，旧单位、建筑、资源、幽灵、动态 blocker 和单例引用无残留。

## 8. 验证

1. 强制请求编译并等待完成，检查编译摘要和控制台错误。
2. 运行 PlayMode 回归测试，所有选定用例通过。
3. 运行场景清理后执行 Project Doctor，确认本次目标类别无未解释错误。
4. 重新打开 `SampleScene` 做基础冒烟检查，确认管理器、网格和关键引用正常。
5. 测试结束恢复 `Time.timeScale=1`，正式场景无测试产生的脏数据或新增对象。
