# 主界面、模式场景与全场景深度整改设计

日期：2026-10-17  
项目：At the Gates / 兵临城下  
状态：布局、设置内容和深度检查方法均已获用户确认

## 一、目标与范围

本次完成三个相互衔接但可独立验收的工作包：

1. **主界面与游戏流程**：优化 MainMenu，加入真实可用的显示/镜头设置，新增三模式选择场景。
2. **全场景深度检查与修复**：检查玩法、场景铺设、网格阻挡、YSort、装饰物落点、资源可达性、UI 遮挡及完整对局。
3. **Demo 回归与 RTS 建议**：修复后重新运行完整流程，记录实证结果，并给出后续整改/扩展建议。

已确认布局为 A「卷轴指挥所」：保留当前卷轴与左右分栏，模式场景使用三张并排卡牌。设置内容为显示＋镜头，不加入当前无法试听的音量设置。

不纳入本次施工：战役/对战实际玩法、人口、肉经济、编队、A-move、桥、哥布林阵营、联网功能、暂停菜单及新的资源体系。战役与对战只做锁定占位。

## 二、主界面、设置与模式流程

### 2.1 场景流程与 Build Settings

流程固定为：

```text
MainMenu
  ├─ 开始游戏 → ModeSelect
  │                ├─ 人机模式 → SampleScene
  │                ├─ 战役模式 → 锁定占位，后期开放
  │                └─ 对战模式 → 锁定占位，后期开放
  ├─ 设置 → MainMenu 内设置面板
  └─ 退出游戏
```

- Build Settings 顺序：MainMenu、ModeSelect、SampleScene。
- ModeSelect 提供返回 MainMenu 的按钮。
- 人机模式沿用现有 SampleScene、AI、胜负与重开逻辑。
- 战役和对战显示锁图标及“后期开放”，不可进入空场景。

### 2.2 MainMenu 优化

- 保留卷轴、左右分栏和既有按钮风格，不全量重建当前 MainMenu。
- 当前 MainMenu 已处于 dirty 状态；施工前按原样备份，采用定向修改，不丢弃其中未保存内容。
- 右上角加入齿轮设置按钮。
- 更新玩法说明：
  - 民房是唯一生产工人的建筑；
  - 金矿是固定地图矿点，不能随意建造；
  - H 为驻守；
  - 小地图支持查看与点击跳转。
- 提供定向、可重复运行的编辑器增强工具；以后主动重建 MainMenu 时也必须保留这些增强，避免一次性场景补丁被覆盖。

### 2.3 设置面板

使用项目内已导入且已验证可用的 `Banner_Vertical`、Ribbon、齿轮、锁和加减图标，不使用无法直接拼接的零件图纸作为整图按钮。

设置项：

1. 分辨率：1280×720、1600×900、1920×1080。
2. 全屏开关。
3. 屏幕边缘平移开关。
4. 镜头移动速度：6～30，默认 18，显示当前数值。
5. 恢复默认和返回。

行为：

- 使用 `PlayerPrefs` 持久保存，场景切换和下次启动仍能读取。
- 分辨率/全屏仅在正式运行时调用屏幕设置；编辑器中只保存，不强行改变编辑器窗口。
- `RTSCamera` 启动时读取边缘平移与镜头速度。
- 设置面板打开时拦截背景按钮输入；返回后恢复主菜单。
- 默认值：1920×1080、全屏开、边缘平移开、镜头速度 18。

## 三、深度检查方法

### 3.1 静态场景与铺设扫描

扫描 SampleScene 的 Tilemap、Building、ResourceNode、Decor、Garnish、单位、摄像机和 UI：

1. **落点合法性**
   - 草丛/灌木是否位于水面、悬崖、无地面格或建筑占地。
   - 水岩是否落在陆地，陆地岩石是否压在树、矿、建筑或其他阻挡物上。
   - 树木、矿点是否互相重叠、越界或被封死。
   - 云和装饰是否进入战斗区域或地图外。
2. **数据与视觉异常**
   - 同坐标重复、异常 Z、缺失 Sprite/YSort、错误 pivot、漂浮底部、异常 sortingOrder。
   - 使用 SpriteRenderer 世界包围盒识别明显错误重叠，同时区分合理前后遮挡。
3. **资源与连通性**
   - 每个矿/树附近是否存在可采集格。
   - 红蓝出生区、固定矿、卸货点和主要进攻路线是否可达。
   - 分离岛屿按区域判断，不要求全图单一连通。
4. **UI 与镜头**
   - 在 1920×1080、1600×900、1280×720 检查 MainMenu、ModeSelect、设置面板、HUD 和小地图。
   - 检查主相机边界、小地图视野框和场景跳转。

### 3.2 运行态碰撞与遮挡

当前移动是网格寻路，不以刚体物理模拟单位碰撞；不通过添加 Rigidbody/Collider 修复视觉或网格问题。

- 代表单位经过草、树、石头、建筑、装饰物的上方、同格和下方，联合检查 sortingOrder 与画面。
- 检查草盖头、漂浮、石头压树、错误穿模及错误遮挡。
- 验证阻挡物仍阻挡路径，非阻挡草丛仍可穿过。
- 覆盖 Warrior、Lancer、Pawn 和代表建筑，不以单点抽查代替整体结论。
- 回归民房产工人、固定矿采集、驻守、近战延迟伤害、AI 建造进攻、小地图及事项 1 的障碍格恢复。

## 四、修复原则与防回归

- 施工前备份当前场景和相关 prefab，只修有量化证据或稳定复现的问题。
- 漂浮/盖头：修 pivot、接地点或 YSort，不乱加碰撞。
- 错误落点：移动到同类型最近合法格；仅删除重复或无必要的对象。
- 阻挡封路：最小搬迁并重新验证区域连通。
- 同步修复生成器，避免下次生成复发；不全量重撒地图、树木或装饰。
- 每项保留修复前后坐标、数量、截图和验证结果。
- 每完成一类修复即重跑既有功能，不允许最后才发现旧功能被破坏。

## 五、最终 Demo 验收

完整运行：

```text
MainMenu → 修改设置并验证保存 → ModeSelect → 人机对局
→ 民房生产工人 → 固定矿采集 → 其他兵种生产
→ 移动/强攻/驻守 → 小地图操作 → AI 建造与进攻
→ 返回与重开验证
```

验收标准：

- 三个模式入口状态正确，战役/对战不会误进入空场景。
- 设置实际生效并能持久化，不遮挡主菜单按钮。
- 所有实证铺设/遮挡问题已修复，未引入新重叠或路径阻断。
- 既有经济、生产、AI、动画、寻路和小地图不回归。
- 编译 0 错误；无本次新增异常。
- 退出 Play 后无临时对象、运行时相机或探针残留，场景保存干净。
